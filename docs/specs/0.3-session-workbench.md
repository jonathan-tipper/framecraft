# Framecraft 0.3 test release

Status: implemented in beta 1; initial UI, installation and shortcut presentation updated by [the beta 2 Mac experience](0.3-mac-experience.md); remaining acceptance gates are recorded in `docs/TEST-NOTES.md`. This specification records the bounded
implementation choices for the [product backlog](https://github.com/jonathan-tipper/framecraft/issues/1).
It is not verification evidence.

## Outcome and scope

Collect intended frames, return to the session after quitting, explain a frame,
and hand off the selected pixels or an ordered offline evidence pack. The user
authorised building the researched enhancements for testing on 28 October 2026.
This promotes annotation and OCR proposals to implementation candidates without
claiming that the user pilot has happened.

Delivery issues: #5, #6, #7, #10, #11, #13, #14, #15, #16 and #17. Research #12
produces a reproducible detector evaluation. #8 produces a capture-targeting
decision record; #9 and #18 retain their human-study/demand gates. Video, audio,
hosting, accounts, automatic summaries and editable-project persistence remain
outside this version. macOS 13 remains the deployment baseline.

## Shared contracts

- An active or paused session cannot accept a new target. Starting clears pending
  source selection. Page-specific commands cannot mutate the hidden editor.
- A saved PNG is acknowledged only after persistence. OCR and review metadata
  cannot discard an acknowledged image. Manual names outrank pending OCR.
- Capture identity is independent of its mutable path. Session metadata has a
  version, bounded input, relative paths and explicit recovery behaviour.
- Opening a saved session never starts capture. Reusing capture settings requires
  source confirmation. Metadata does not contain OCR transcripts or editor layers.
- Original and Saved edited variants decode the chosen PNG unchanged. Current
  edits render the current document revision once. The resolved pixel snapshot
  governs preview, clipboard, drag and pack output. No fallback to an original
  when an edited file is missing; no double styling of flattened PNGs.
- Drag/pack filenames are neutral sequence names. Titles and captions start blank
  or neutral. Reusing a capture title requires explicit confirmation in the output
  preview. No original paths, names, OCR text or metadata enter exports implicitly.
- OCR copying operates only on current rendered pixels. It requires a current
  text preview and explicit Copy; failure/cancellation leaves the clipboard alone.
- All annotation types can be selected/moved/deleted. Plain multiline text and
  numbered steps use one deterministic renderer. Redactions are last and opaque.
- Quitting/replacing an edited document requires export, discard or cancellation.
  Export failure preserves edits. Saving a PNG does not save editable layers.

## Concrete implementation choices

- Store a bounded JSON manifest beside PNGs and recent-session references in the
  user's application-support directory. Use atomic writes and a per-session
  writer lock. Do not index arbitrary folders or automatically delete originals.
- Legacy-folder import previews recognised files and requires confirmation.
  External relinks are copied into the session; never retain outside paths.
- Annotation fonts are embedded and work offline. The first release supports the
  bundled font's glyphs with an explicit replacement glyph, not complex-script
  shaping or exact typography portability from system fonts.
- First pack format: a new folder with `index.html` and neutral-named flattened
  PNGs, relative references, escaped user text and no scripts/external assets.
  Stage before publication and never overwrite an existing destination.
- Native menu controls reuse the session command path. Shortcut configuration
  changes only while stopped. Stopped settings survive restart, capture does not.
- Unattended capture has a deadline; interactive selection remains cancellable
  by the user. Errors distinguish permission, source and destination recovery
  where the platform provides sufficient evidence.

## Implementation plan and ownership

| Slice | Files/responsibility | Verification | Dependencies/retirement |
| --- | --- | --- | --- |
| Persistence and review | `session.rs`, `library.rs`, `session_ui.rs` | round trips, missing/malformed files, races, interruption, filesystem limits, UI state | preserve safe PNG store; retire in-memory-only review |
| Annotation and OCR primitives | `editor.rs`, `naming.rs` | geometry/text/redaction fixtures, full-text order, synthetic native OCR | preserve last-pass redaction and local-only recognition |
| Capture and native controls | `capture.rs`, `session_runner.rs`, native/settings modules | worker lifecycle/failure tests, bounded capture, synthetic change corpus | replace uninjectable boundaries; retain macOS 13 adapter |
| Integrated workflows | `app.rs`, output/pack module, CLI | page-command tests, stale OCR cancellation, variant equality, escaped export, no-clobber | depends on shared APIs; retire duplicate output paths |
| Test distribution/docs | Cargo/packaging/CI, README and guides | fmt, tests with/without UI, strict Clippy, release build, bundle inspection | no release claims for unrun native checks |

Each slice is reviewed before final integration. Test user/data boundaries rather
than implementation details. Record unperformed multi-Mac, permission, VoiceOver
and human usability checks honestly. The distribution target is an ad-hoc signed
test bundle and a reviewable GitHub PR, not a notarised general release.

## Release gate

Required automated checks: formatting; locked all-target tests; no-default-feature
tests; strict Clippy; release compilation; synthetic export and reopen round trips.
Native smoke checks and the remaining desktop matrix are recorded in
`docs/TEST-NOTES.md`. Any remaining material limitation appears in the README,
release notes and GitHub acceptance evidence rather than being hidden by closing
an issue. User studies cannot be replaced by synthetic tests.

## Retires

Remove the target mismatch, hidden-editor shortcuts, in-memory-only session review,
hard-coded-only shortcut configuration and redundant output resolution. Preserve
originals, collision protection, source-coordinate edits and offline operation.
