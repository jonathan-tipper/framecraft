# Mac capture experience: beta 2

This records the beta 2 baseline. The [native editor experience contract](editor-native-experience.md) governs the beta 3 development changes to cancellation, Close screenshot, properties, pixelation and the editor shell. Its pending native checks do not change the historical beta 2 evidence.

Issue [#20](https://github.com/jonathan-tipper/framecraft/issues/20) records the user's first-run feedback. Beta 1 opened a session form, exposed raw shortcut syntax and had no installation package. Its feature checklist did not establish that the basic capture task was usable.

## Direction

For a Mac user who needs a screenshot now, Framecraft should open with an obvious capture action, use familiar Mac controls and get out of the way while the user selects their content.

- Start with a single screenshot. Repeat-capture sessions are a separate secondary task.
- Make commands visible before teaching shortcuts. Use Command and Option, with their symbols as supporting information.
- Use the menu bar as a persistent entry point and the editor as a place to review the result.
- Keep copy and save visible; disclose presentation styling and collection tuning when needed.
- Preserve explicit capture boundaries, unsaved-edit protection and honest error states.

## Interface

Use the installed macOS system font, neutral light surfaces, a blue action colour, restrained borders and compact grouped controls. There is no new web wrapper or runtime service. The image compositor and session worker remain Rust. Reading a system font at runtime does not bundle or redistribute it.

Initial view: Screenshot tab, Capture Area as the main action, Window and Screen alternatives, Open Image and a short explanation of dragging on screen. No disabled annotation toolbar or collection form competes with that action. A screenshot opens the editor with copy/save and annotation tools; background styling is optional. A Sessions tab contains repeated collection and saved-session review.

Menu bar: a capture-frame icon, Capture Area, Capture Window, Capture Screen, Open Framecraft, Keyboard Shortcuts and Quit. Separate session actions show collection state and are enabled only when applicable. One-off capture is unavailable during an active session and while replacement decisions or background file work are pending. Quit uses the existing save/discard/cancel and persistence-drain path.

Keyboard settings: name Command, Option, Control and Shift explicitly; select modifiers and a key, show the resulting binding and explain where it works. Session shortcuts register only during a session. Existing stored key strings remain compatible; implementation tokens never need to be typed.

## Capture and recovery

Click Capture Area → hide the window and capture controls → macOS crosshair → drag rectangle → editor. Escape restores the unchanged document. Unsaved edits prompt before replacement. Screen-access failure gives a route to System Settings; permission is never granted automatically. A capture session must be stopped before starting a conflicting one-off capture.

Installation uses a versioned DMG with Framecraft.app and an Applications link, plus a repeatable local install script. An app icon identifies the bundle in Finder and the Dock. Ad-hoc signing remains a beta limitation; Developer ID/notarisation is not implied.

## Acceptance and evidence

Use issue #20's criteria. Check initial view, native menu commands, capture cancellation, captured result, shortcut configuration, unsaved edits, install/package structure and documentation. Tests cover routing/guard and shortcut conversion behaviour. Record observed native results separately from unperformed permission, display, receiving-app and VoiceOver checks. No new demand or accessibility-conformance claim follows from this redesign.

References: [Apple menu guidance](https://developer.apple.com/design/human-interface-guidelines/menus) and [Mac keyboard symbols](https://support.apple.com/guide/mac-help/cpmh0011/mac). The user feedback is the reason for this change; the references establish platform conventions.
